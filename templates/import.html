Import equipment from CSV

Most farms already have a machinery list in a spreadsheet. The importer reads it with Python's csv.DictReader, runs every row through the same validation function the Add-Equipment form uses, then inserts the surviving rows with a single executemany(). Rows that fail are listed back with the line number and the reason, and are not written.

Upload a file

Maximum 2 MB. The first line must be the header row.

Two files ship with the project for testing: data/sample_equipment.csv (5 clean rows) and data/sample_equipment_with_errors.csv (2 good rows and 7 broken ones, one per validation rule).

Required columns

  • name — required, ≤ 100 characters
  • equipment_type — Tractor, Combine, Planter, Sprayer, Baler, Tillage, Loader, Truck, Irrigation or Other
  • manufacturer — required
  • model — optional
  • year — a whole number between 1900 and 2100, or blank
  • serial_number — must not already exist in the database, and must not repeat within the file
  • purchase_date — YYYY-MM-DD, or blank
  • status — Operational, Needs Repair, In Repair, Out of Service or Retired

Importing from Excel instead

The application accepts CSV only, because csv is in the Python standard library and needs no extra dependency. An .xlsx file can be loaded into the same database with a few lines of pandas — worth knowing even though the app does not require it: 

import pandas as pd, sqlite3

# 1. Read the spreadsheet (needs: pip install pandas openpyxl)
df = pd.read_excel("machinery.xlsx", sheet_name="Equipment")

# 2. Keep only the columns the table has, in the right order
cols = ["name", "equipment_type", "manufacturer", "model",
        "year", "serial_number", "purchase_date", "status"]
df = df[cols]

# 3. Validate before writing — pandas will happily insert nonsense
df = df[df["name"].notna() & df["manufacturer"].notna()]
df["purchase_date"] = pd.to_datetime(
    df["purchase_date"], errors="coerce").dt.strftime("%Y-%m-%d")

# 4. Append to the existing table
conn = sqlite3.connect("database/farmfix.db")
conn.execute("PRAGMA foreign_keys = ON;")
df.to_sql("equipment", conn, if_exists="append", index=False)
conn.commit()

Two traps worth knowing. First, to_sql(if_exists="replace") drops and recreates the table, destroying the primary key, the foreign keys and every CHECK constraint in schema.sql — only "append" is safe against a table you designed yourself. Second, to_sql does no validation at all, which is why step 3 exists: pandas will write a row that the application's own form would have rejected.
